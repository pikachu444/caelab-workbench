# Windows에서 실제 사용 흐름 확인

이 절차는 실제 Windows 창·입력·외부 프로그램·저장 파일을 대조합니다. 제품 종료 조건은 [DESIGN §12](../../DESIGN.md#12-이행-계획), 현재 미확인은 [CURRENT_STATE](../../CURRENT_STATE.md)가 정본입니다. Qt offscreen이나 framebuffer만으로 이 절차의 통과를 주장하지 않습니다.

## 준비

[시작 가이드](../../docs/tutorials/workbench_quickstart.md)의 설치·외부 실행 파일 설정을 사용합니다. 검사할 코드 SHA, 앱/솔버 버전, 사용 입력, Windows 버전·해상도·현재 DPI를 기록합니다. 기존 사용자 프로젝트·레이아웃을 보존한 별도 작업 사본을 사용합니다. 소스/venv 실행과 standalone EXE 실행은 구별합니다.

## 확인할 사용자 행동

| 흐름 | 실제 확인과 보존할 결과 |
|---|---|
| 시작·프로젝트 | 오류 없이 런처가 열림. 역할에 맞는 프로그램을 추가하고 여러 같은 프로그램의 독립 노드를 배치·연결할 수 있음. 고정 5상자를 요구하지 않음 |
| 파일·상태 | 입력·편집 문서·내보낸 출력이 구별됨. 변경/누락·미설치 안내와 하류 stale 표시가 실제 파일에 맞음 |
| 저장·복구 | 추가→연결→해제→제거→저장→전체 종료→새 프로세스 재열기→복원. 원본·실행·대화를 보존하고 삭제한 연결/숨은 직접 입력이 재발하지 않음 |
| 독립 프로그램 | 선택 노드의 같은 입력/문서/실행 결과가 해당 CAD·전처리·해석·후처리·전문가 창에 전달됨. 다른 실행이나 대체 화면으로 성공 처리하지 않음 |
| 계산·취소·이력 | 명시적 계산만 실행함. 단계별 로그·실패·취소·선택 이력을 보존하고 저장본에서 같은 실행을 다시 읽음. RAD는 Starter·Engine 및 partial을 따로 확인 |
| 결과 | 같은 실행의 선택 프레임·필드·단위·출처를 실제 화면과 파일로 대조. VTK가 검으면 OS 창 캡처와 별도 framebuffer를 구분해 원인을 조사함 |
| 전문가 | 기존 자료·답변·초안이 저장·재열기됨. 제안만으로 원본을 바꾸거나 계산하지 않음. 열기만으로 새 LLM 요청이나 첨부를 만들지 않음 |
| 한국어 입력 | 실제 IME preedit→수정→Enter 확정과 전송을 구별. Shift+Enter 줄바꿈·초안 저장·새 프로세스 재열기. 붙여넣기나 composing 플래그만으로 실제 IME 통과라고 쓰지 않음 |
| 화면·테마 | 정상/좁은 창·최대화/복원·라이트/다크에서 선택·열기·편집·저장 명령에 접근. 실제 최소 폭·현재 OS DPI·앱 배율을 구별하고 측정하지 않은 DPI 통과를 주장하지 않음 |
| MDO | 실제 연구·관측·예측을 구별. 선택점 적용은 사용자 명령으로 INP를 백업·치환하고 재해석은 별도로 실행. CAD 재생성으로 설명하지 않음 |

## 판정 기록

각 행동의 코드/입력, 재현 순서, 실제 OS 창 캡처, 파일·상태 대조, 실패와 미실시 이유를 함께 남깁니다. OS 캡처의 VTK 영역과 별도 renderer 캡처를 구별합니다. 기존 입력을 교정에 사용했다면 최종 독립 입력으로 다시 세지 않습니다. 기존 검사와 겹치는 수치를 합산하지 않고, 관련 미해결 지적이 있으면 해당 흐름의 완료로 처리하지 않습니다.
