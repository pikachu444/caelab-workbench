## 결론과 감사 범위

사용자 비판을 전부 개선 대상으로 수용한다. **반박 근거 없음·비판 수용.** 핵심 문제는 문체보다 증거와 표현의 불일치다. 빈 자체 작업 창을 FreeCAD 전처리로 설명했고, 합성 수치로 채운 화면을 실제 공학 계산처럼 제시했으며, 실행 근거가 없는 비교 수치를 달성 결과와 혼용했다. README의 ‘상용급’, ‘공인’, ‘완결’과 CURRENT_STATE의 ‘가짜 수식 전면 박멸’은 감사 대상 코드로 뒷받침되지 않는다.

사실관계는 정확히 구분한다. 튜토리얼 파일은 존재한다. 실제 CalculiX 연결 코드와 과거 다른 사례의 실행 자료도 존재한다. 그러나 그것들이 **현재 GE 브래킷의 28,450절점 C3D10 모델을 50회 계산해 36.2% 감량했다는 증거는 아니다.** 36.5% 역시 출처가 검증된 상용 문헌값이라고 확정할 수 없다.

README, DESIGN, ARCHITECTURE, CURRENT_STATE, 관련 AGENTS, 기존 리뷰·개선 계획, 벤치마크 2종, 튜토리얼 2종, MDO GUI·배치 입구·관련 테스트와 Git 이력을 대조했다. `docs/images/`의 PNG 8개를 직접 열어 확인했다. 읽기 전용 CAE 자문으로 수식과 모델·출력 의미, 공식 출처를 교차검토했다. 제품 코드 수정, 새 솔버 캠페인, 상용 솔버 비교, 실제 GUI 조작 검증은 이번 감사에서 수행하지 않았다.

## 2. MDO 테마 편중과 차트의 출처 혼합

테마 비교는 사용자 설정 안내로는 유효하지만, 모델·입력·계산·결과의 연결을 이해하는 데 우선하지 않는다. README는 프로그램 간 파일 전달과 사용자가 얻는 결과를 먼저 설명해야 한다. 다크/라이트 비교는 사용자 가이드의 설정 절로 옮기고 README의 MDO 화면은 출처가 명확한 대표 화면 하나로 줄이는 것이 적절하다. 테마 기능 삭제나 모든 기둥에 같은 수의 이미지를 배분하는 작업은 필요 없다.

추가로 현재 전체 MDO 스크린샷은 6변수 GE 이름의 데모지만, `screen_mdo_studio_dark_pareto/surface/tornado.png`는 `width`, `height`의 **2변수 보 예제**다. 같은 연구의 연속 화면으로 읽히는 구성에서 서로 다른 데이터가 섞여 있다. 반응 곡면 이미지는 3D 회전 곡면이 아니라 2D 곡선이다.

[window.py](../../apps/workbench_qt/mdo_studio/window.py) 449–476행의 현재 민감도 연결은 Spearman 상관계수다. 실패하거나 표본이 부족하면 변수 순서로 만든 임의 막대를 표시한다. README의 Sobol 1차/총차 지수 설명과 맞지 않는다. 478–508행은 첫 두 변수로 GP를 적합하며, 6변수 GE 물리 모델의 검증된 반응 곡면으로 볼 수 없다. [response_surface_view.py](../../apps/workbench_qt/mdo_studio/views/response_surface_view.py) 71행은 출처 구분 없이 `Actual CAE Evaluations`로 점을 표시한다. 합성 예제도 같은 표시를 받는다.

수정 시 차트마다 연구·데이터 출처·단위·방법을 맞춘다. 수식 예제는 수식 예제로 표시하고, 실측·대리모델 예측·미평가를 구분한다. 근거 없는 민감도 막대 대신 ‘자료 부족/분석 실패’와 원인을 표시한다. 실제 데이터 없이 보기 좋은 Pareto 곡선이나 합격점을 만들지 않는다.

## 4. 벤치마크: 실측으로 제시할 수 없다

### 4.1 데모의 수식은 어디에서 무엇을 하는가

[window.py](../../apps/workbench_qt/mdo_studio/window.py) 196행에서 기본 창을 열면 `_create_demo_ge_bracket_study()`가 호출된다. 301–365행은 25개 설계점을 생성하고 다음과 같이 응답을 채운다.

```python
mass = (tb*120.0 + tr*80.0 + rf*15.0 + db*40.0 + tw*30.0 + hs*20.0)*0.00018
stress = 48000.0/(tb**0.8*tr**0.7) + 85000.0/(db**1.1*tw**0.5)
disp = 320.0/(tb**1.2*hs**0.8) + 180.0/tr
rec.status = "COMPLETED"
rec.duration_sec = 1.85 + float(np.random.uniform(0.1, 0.5))
```

엄밀히 말하면 응력·변위 식은 다항식이 아니라 비정수 지수와 역수를 포함한 식이다. 감사상 핵심은 수식의 분류가 아니라 실제 FE 결과에서 유래하지 않은 합성 응답이라는 점이다.

위 식은 표와 차트를 채우는 합성 응답 생성기다. 이 함수에는 CAD 읽기, 메시 생성, 네이티브 솔버 제출, 결과 판독, FE 학습자료를 이용한 계수 적합이 없다. 실제 FEA로 보정·검증한 대리모델이라는 근거도 없다. 화면 개발용 수식을 쓰는 것 자체와 그것을 GE 공학 결과로 명명하는 것은 구분해야 한다. 작성자의 의도는 확인할 수 없지만 실행상 역할은 명확하다.

CAE 자문이 코드와 같은 seed·생성 순서로 수식만 재계산한 결과(솔버 미실행):

| 항목 | 데모의 25점 범위 | 문서와의 관계 |
|---|---:|---|
| mass | 0.874946–1.364591 | 문서의 kg 실측으로 인정할 출처 없음 |
| stress | 892.798–2451.399 | 650 이하인 점은 **0/25** |
| disp | 10.788996–28.453315 | 문서의 0.75 이하 조건과 양립하지 않음 |

문서 기준 치수 `(15, 12, 6, 60, 10, 35)`를 대입하면 mass=1.125, stress≈1263.397, disp≈15.722다. 문서 기준값 1.85kg·742MPa와도 다르다. 필렛 변수 `rf`는 응력식에 전혀 없으므로 ‘필렛 6→11.5mm 변경으로 응력 615.4MPa 달성’도 이 수식으로 설명되지 않는다. 문서는 벽 두께를 이산형으로 규정하지만 데모는 연속형이며, 처짐·볼트 반력 제약도 데모 제약 목록에 없다.

### 4.2 Run 버튼의 실제 계산 경로도 GE 모델과 다르다

window 550–653행에는 JobManager를 통한 실제 네이티브 배치 연결이 있다. 그러나 덱이 없는 기본 데모에서는 604–616행이 **8절점·C3D8 요소 1개·STEEL 재료의 동일 큐브**를 각 점의 입력으로 만든다. GE의 6개 변수는 해당 물리 입력에 반영되지 않는다. 이 경로에서 ccx가 실행되더라도 GE 28,450절점 C3D10 티타늄 브래킷의 최적화가 아니다. 실제 덱을 연 경로와 기본 데모 경로를 혼동해서는 안 된다.

[test_mdo_studio_gui_live.py](../../tests/test_mdo_studio_gui_live.py) 35–68행은 Python subprocess가 가짜 FRD와 `Total mass: 1.482`, CalculiX 완료 문구를 출력하도록 실제 실행 명령을 monkeypatch한다. 90행 이후의 GUI 배치 검사는 3점으로 줄인 모의 실행이다. 이 테스트는 신호·표 갱신 검증으로는 유효하지만 ‘genuine ccx’라는 문자열이나 통과 개수는 실제 CCX/GE 계산 증거가 아니다.

응답 추출 함수 154–166행의 mass는 로그 정규식 값이다. CURRENT_STATE 10행의 ‘요소 체적/밀도 기반 질량 계산’ 주장과 다르며 kg 환산·단위 출처도 여기서 확인되지 않는다. CAE 자문은 CalculiX 공식 매뉴얼의 일관 단위 및 EMAS 출력, FRD 응력 위치를 대조했다. [CalculiX 2.23 매뉴얼](https://www.dhondt.de/ccx_2.23.pdf)의 §3, §5.1, §7.53을 기준으로 질량 단위와 응력의 절점 외삽/평균화·프레임 범위를 선언한 뒤 비교해야 한다. 같은 숫자 이름만으로 상용 솔버의 최대응력과 동등하지 않다.

### 4.3 36.5% 대 36.2%의 정확한 판정

[벤치마크 문서](../benchmarks/commercial_mdo_benchmark_calculix.md) 제목과 §3은 ‘계획/목표 사양’이라고 쓰지만, 49행은 36.2%와 615.4MPa를 ‘동시 달성’으로 서술하고 118–121행은 정밀 수치 옆에 검증 통과 상태를 붙인다. 목표·모듈 검사·실측 결과가 섞여 있다.

| 주장 | 감사 판정 | 정정 방식 |
|---|---|---|
| caelab 36.2%, 1.180kg, 615.4MPa | 실제 GE 실행과 연결된 입력·로그·결과·실행 ID를 찾지 못함. 데모 수식 결과와도 맞지 않음 | 실측표에서 철회. 유지하려면 근거와 승인된 목표임을 별도로 제시; 근거 없는 정밀 목표는 삭제 |
| DoE 50회, 3분 10초, 5배 이상 단축 | 해당 모델의 50회 실행 및 측정 조건 근거 없음. 기본 데모는 25점, duration은 난수 | 측정값처럼 쓰지 않음. 실제 시간·호출 수 확인 전 ‘미측정’ |

‘실측이 아니라 상용 문헌과 목표를 비교한 것’이라는 해명도 충분하지 않다. 상용 수치 자체의 출처부터 검증해야 한다. 공식 자료를 직접 확인한 결과 문서가 로어 암 출처로 쓴 **OS-T:2000은 Structural C-Clip**, **OS-E:0105는 Follower Force가 작용하는 Cantilever Beams**다. [Altair OS-T:2000](https://2023.help.altair.com/2023.1/hwsolvers/os/topics/solvers/os/design_reference_for_structural_c_clip_r.htm), [Altair OS-E:0105](https://help.altair.com/hwsolvers/os/topics/solvers/os/cantilever_beam_follower_forces_example_problem_intro_r.htm).

GE 공식 소개는 엔진 취급용 브래킷, 원본 2.033kg, 우승작 약 84% 감량을 설명한다. 현 문서의 보조장치 지지·기준 1.85kg·OptiStruct 36.5%를 입증하지 않는다. 다른 연구나 변형 사례가 존재할 가능성은 남지만, 그것이 현 문서의 수치 출처라는 증거가 필요하다. 84%를 새 상용 비교치로 대체해서도 안 된다. [GE 공식 챌린지 소개](https://www.ge.com/news/reports/jet-engine-bracket-from-indonesia-wins-3d-printing).

사용자에게 공개할 정정 문안:

> 현재 제공되는 GE 브래킷 이름의 MDO 데모는 솔버 계산 없이 수식으로 만든 25개 예시 데이터를 표시합니다. 실행시간도 측정값이 아닙니다. 덱이 없는 상태에서 실행하면 별도의 8절점 큐브 입력을 사용하며, GE 브래킷 해석이 아닙니다. 저장소에서 GE 28,450절점 모델의 50회 CalculiX 계산과 연결된 실행 증거는 확인되지 않았습니다. 기존 36.2% 감량·615.4MPa·3분 10초는 실측 결과에서 철회합니다. OptiStruct 36.5% 또한 원문 출처가 확인될 때까지 공식 비교값으로 사용하지 않습니다. 단위·모의 연결 테스트 통과와 실제 공학 벤치마크 완료를 혼동하게 작성한 점을 정정합니다.

### 4.4 문구 정정과 함께 막아야 할 코드 위험

window 763–777행은 새 연구/데모 전환 시 이전 `current_deck_path`, `template_deck`를 지우지 않는다. 525–548행의 적용 동작은 연구와 덱의 연결·출처를 확인하지 않고 현재 덱에 쓰며 예외 뒤에도 `Applied` 메시지를 표시한다. 348행의 합성 `COMPLETED` 상태는 setup_dock의 적용 버튼을 활성화한다. 이전 덱에 공통 토큰이 있다면 데모 값이 실제 원본에 들어갈 수 있는 코드 경로다. 파일을 파괴하는 재현은 하지 않았다.

따라서 ‘데모’ 배너만 붙이는 것으로 부족하다. 합성 연구의 실행/실덱 적용을 차단하고 새 연구 전환 시 바인딩을 초기화해야 한다. 실측 후보의 적용은 올바른 입력 개정과 대상 덱인지 확인하고, 백업·쓰기 성공 후에만 성공으로 표시해야 한다.

### 실제 이미지 촬영 목록

1. 연결된 부모 프로젝트: 각 프로그램 이름, CAD/INP/결과 파일, 상태를 읽을 수 있는 화면.
2. 실제 FreeCAD FEM: 형상·모델 트리, 메시, 재료·하중·구속을 보여주는 2–3개 상태. 자체 MainWindow로 대신하지 않음.
3. NativeAnalysisWindow: 선택 입력, 실행/종료 상태, 실제 로그와 결과. 로그가 증명하지 않는 ‘잔차 수렴 차트’를 캡션에 추가하지 않음.
4. 실제 ParaView: 같은 run의 결과 필드, 단위·범례·하중 케이스/프레임을 표시. 외부 논문 그림을 제품 실행처럼 쓰지 않음.
5. 전문가: 동일 실행 자료가 첨부된 상태와 근거 연결. 실제 답변을 보여주려면 기존 유효한 실행 기록 또는 별도 확인된 답변임을 명시.
6. MDO: 실제 연구의 변수·결과·출처와 선택 후보. 합성 예제를 쓰는 경우 화면과 캡션 모두 합성이라고 명시하고 실제 검증 화면을 대신하지 않음.

각 캡션은 ‘어느 프로그램에서 어떤 파일을 열고 무엇을 수행한 화면인가’를 답해야 한다. 캡처 시점의 버전·입력·실행 참조는 기존 작업 기록과 원자료에 남긴다. 이미지 생성이나 숫자 합성으로 빈 영역을 채우지 않는다.

### 실제 GE 비교 완료 조건

- 원 CAD/메시와 라이선스·출처·해시, 솔버 버전, 단위계, 재료, 하중·구속·접촉, 출력 위치·평균화·프레임을 고정한다. 문서의 4개 하중과 ‘3개 모두’ 같은 내부 모순도 해소한다.
- C3D10 솔리드의 필렛·보스 치수는 문자열 토큰만 바꿔서 자동 재생성되지 않는다. 네이티브 CAD 갱신·재메시 또는 검증된 메시 변형을 통해 실제 기하 변화와 조건 영역 유지, 메시 품질을 확인한다.
- baseline의 질량·반력 평형·변위·응력과 필요한 메시 수렴을 확인한다. 비교 허용오차와 제약은 결과를 보기 전에 정한다. ‘28,450개’를 맞추기보다 실제 재현 가능한 모델 규모를 기록한다.
- 50점 캠페인을 수행한다면 각 후보의 물리 입력·실제 명령·원로그·종료/판독 상태·소요시간·결과를 run 저장소에 남긴다. 실패·재시도·캐시·최종 검증 호출 수를 분리한다. 런타임 난수나 모의 subprocess는 포함하지 않는다.
- 대리모델은 출처 있는 FE 표본에 적합하고 독립 검증점으로 오차를 평가한다. 예측 후보를 실제 솔버로 재평가해 제약과 최종 질량을 확인한다. 학습용 점의 일치나 GP 불확실성 띠만으로 공학적 정확성을 승인하지 않는다.
- 상용 도구와는 같은 문제·변수 영역·하중·제약·응답 정의·계산 예산을 비교한다. 위상 최적화와 6변수 치수 최적화를 동일 문제로 간주하지 않는다. 시간 비교에는 하드웨어·코어 수·재메시·학습·검증 포함 범위를 기록한다.
- 다른 사람이 동일 입력과 명령으로 재현할 수 있어야 한다. 결과는 실제 나온 수치로 보고하며 기존 36.2%나 615.4MPa에 맞춰 입력·제약·허용오차를 조정하지 않는다.

이번에 수행한 것은 코드·문서·PNG·Git 이력 감사, 공식 웹 자료 대조, 데모 수식의 독립 계산 및 시정 계획 작성이다. 실제 CCX/상용 솔버 재실행, 새 실화면 촬영, 전체 제품 회귀는 하지 않았다. 과거 증거 폴더는 파일 존재만 확인했으며 모든 외부 실행 자료를 전수감사한 것은 아니다. 따라서 ‘어디에서도 한 번도 실행된 적 없다’가 아니라 **‘현재 공개 주장과 연결된 실행 증거가 없고, 제공 데모 경로는 그 계산을 수행하지 않는다’**가 정확한 판정이다.

문서와 코드의 오류를 확인했다고 작성자의 고의나 기만 의도를 추정하지 않는다. 다만 사용자가 계산의 진위를 판단할 수 없게 만든 상태는 분명한 결함이며, 이번 감사 보고서가 작성됐다는 이유로 해소 처리하지 않는다.
