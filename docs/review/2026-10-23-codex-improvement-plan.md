## 1. 도달해야 할 사용자 행동

사용자가 자기 프로젝트를 만들거나 열고, 실제 FreeCAD FEM 파일을 선택한다. 네이티브 프로그램에서 형상·메시·재료·조건을 편집하고 CalculiX 입력을 작성한다. 워크벤치는 그 입력을 받아 계산하고, 실제 결과 파일을 ParaView로 열며, 같은 실행의 설정·로그·결과를 전문가에게 전달한다. 사용자는 제안을 검토해 적용하거나 네이티브 프로그램에서 변경하고 다시 계산한다. 저장 후 재열면 프로젝트·실행 결과·토론이 유지되고 자동 계산이나 LLM 호출은 일어나지 않는다.

초기 사용자 모델 경로는 CalculiX 하나에 집중한다. 이 경로의 네이티브 입력 수용 범위를 보조 변환기의 요소·재료 지원표로 제한하지 않는다. 압력·자중·마찰 접촉·비선형 재료·사면체·육면체·셸은 1단계 종료 조건을 확인할 입력 범위다. 네이티브 작성기에서 특정 조합을 지원하지 못하면 그 제한과 가능한 원 덱 경로를 정확히 기록한다. 불가능한 조건을 생략해서 통과시키지 않는다.

Windows 실화면은 과거 보류 후 사용자 요청으로 재개했다. 2026-10-26 현재 FreeCAD 작성·CalculiX 버튼 계산·ParaView·전문가 자료 전달과 실제 구독 답변을 확인했다. 부모 전체 조작·일부 전체 재개·IME·창 크기·배율과 최종 독립 입력은 남아 있다. 정확한 기존 증거·미완료·담당은 CURRENT_STATE 최신 표, 재개 명령과 동작은 NEXT_SESSION을 따른다.

최소 프로젝트 문서는 다음 정보만 소유한다.

- 프로그램 노드의 식별자, 역할, 연결된 네이티브 문서·입력·출력 참조.
- 연결의 출발 출력과 도착 입력. 선만 그려 놓은 연결은 저장하지 않는다.
- 파일 경로, 프로젝트 내부/외부 여부, 자동으로 얻은 개정 식별 정보, 단위 선언과 그 출처.
- 실행별 입력 스냅샷 참조, 작업 상태, 결과 파일, stdout/stderr, 판독 상태, 선택 실행.
- 실행에 연결된 토론·제안·적용 이력과 사용자의 제약.

제안하는 프로젝트 배치는 `project.json`, `runs/<run-id>/`, `discussions/`다. 이름 자체는 고정 요구가 아니다. 외부 CAD를 무조건 복사하지 않되, 계산 시점 입력과 현재 편집 중인 원본을 혼동하지 않아야 한다. include 파일을 쓰는 덱은 필요한 참조를 함께 보존한다. 임의 경로의 원본을 실행 결과로 덮어쓰지 않는다.

상태는 다음을 구별한다: 프로그램이 설치됨, 입력이 준비됨, 실행 중, 프로세스 종료, 결과 판독 완료, 상위 입력 변경으로 결과가 오래됨, 실패, 취소. 설치됐다는 이유로 결과를 '최신'이라고 표시하지 않는다.

### P1. 잘못된 성공과 조건 누락 차단

수정 내용:

1. 보조 변환 실행 직전에 입력·지원 검사를 수행한다. 오류가 있으면 덱 생성과 프로세스 호출을 하지 않고 객체 위치를 가진 오류를 반환한다.
2. 단계·재료·하중·접촉·단면·초기조건·출력 요청·증분 옵션 중 실제로 쓰지 않는 항목을 조사하고, 의미를 잃는 입력은 거부한다. 새 물리 기능을 구현하는 작업으로 확대하지 않는다.

4. 실행·판독 예외가 발생해도 작업을 failed로 끝내고 원인을 보존한다. 전체 로그를 실행 폴더에 저장하고 화면에는 꼬리를 보여 준다.
5. ModelEvaluator가 딕셔너리 결과의 실패·취소·부분 실패를 보존하게 한다.
6. 요약의 solver_id와 단위를 실제 결과에서 얻는다. 단위를 알 수 없으면 사용자 선언을 받으며 SI로 추정하지 않는다.
7. RAG 검색의 솔버 제한을 유지한다. 해당 자료 없음과 색인/서비스 오류를 구분해 반환한다.

- **[보완 F2]** 평가 질문의 선정·조정 사용 여부, 솔버별 분모와 근거 조각을 남긴다. 실제 구독 LLM의 연구팀 끝단 확인은 DESIGN §10의 별도 완료 근거이며, 로컬 2회전 또는 검색 Hit@5로 대체하지 않는다. 근거 없는 질문·잘못된 제안은 답변 보류 또는 미적용 상태로 확인한다.

### P5 이후 재발 방지 — CI 신설 (P2에서 이동)

**[정정 C6a]** 이 항목은 결함 수정 자체가 아닌 재발 방지다. P5의 본선 연결 뒤에 수행하며 P2~P5의 완료 조건이나 다음 단계 착수의 선행 조건으로 삼지 않는다. P1~P7의 기능 구현 순서는 유지한다.

대상: `.github/workflows/`의 제품 테스트. Python 3.11 이상에서 PySide6를 포함한 제품 테스트를 필수 실행하는 CI를 둔다. solver 실행은 설치가 있는 별도 경로로 구분하고 skip 이유를 남긴다. 핵심 GUI 검사가 조용히 skip된 채 통과로 취급되지 않게 한다. 해당 수정의 관련 테스트를 직접 실행하는 기존 규칙은 이 이동과 무관하게 유지한다.

### P6. 사용자 제안 적용·재실행·저장·재개

대상: 프로젝트 저장 모듈, `workbench.py`, `jobs.py`, 독립 전문가 프로그램 연결부, 네이티브 어댑터.

수정 내용:

1. 제안은 대상 네이티브 객체/파일, 이전 값, 변경 값, 이유를 포함한다. 내부 StructuralModel 경로만을 전체 제품의 제안 언어로 삼지 않는다.
2. 자동 적용을 지원하는 변경은 사용자 클릭 후 네이티브 API 또는 검증 가능한 파일 편집 경로로 실제 원본에 반영한다. 이전 개정·값이 다르면 거부한다. 지원하지 않는 변경은 '전용 프로그램에서 수정' 안내로 유지하고 적용 완료라고 표시하지 않는다.
3. 실제 원본을 변경할 때 복구 가능한 개정을 보존한다. GUI의 표시용 캐시만 바꾸고 적용했다고 하지 않는다. 네이티브 재작성과 다음 실행까지 같은 입력 계보를 유지한다.
4. 프로젝트·노드·연결·선택 실행·결과 참조·대화·제약·제안 상태를 저장하고 복원한다. JSON은 원자적으로 갱신하며 외부 참조 유실은 구체적인 파일 위치를 알려 준다.
5. 다른 이름으로 저장 시 프로젝트 내부 상대 경로를 재기준화하고 외부 참조 정책을 유지한다. 새 프로젝트를 열 때 이전 결과·선택·대화 캐시를 잘못 재사용하지 않는다.

완료 검사:

- 사용자가 한 네이티브 입력 값을 바꾸고 재계산하면 실제 덱·결과가 바뀌며 같은 토론에 새 실행이 연결된다.
- 오래된 제안은 거부된다. 제안 적용과 실행은 각각 사용자 행동이다.
- **[추가 C6b — 범위 제한 완료 검사]** 자동 적용을 지원하지 않는 변경을 제안받으면 '전용 프로그램에서 수정' 안내와 미적용 상태를 유지한다. 원본·표시용 캐시를 변경하거나 적용 완료로 표시하지 않는다. 이 검사를 통과하기 위해 새 자체 편집기나 모든 네이티브 객체의 자동 적용 기능을 구현하지 않는다.
- 앱 종료 후 새 Workbench 인스턴스로 재열어 결과와 대화를 이어 간다. 열기만으로 프로세스·네트워크 호출이 발생하지 않는다.
- 결과 파일 누락·프로젝트 이동·부분 저장 실패에 대해 성공이나 빈 프로젝트로 위장하지 않는다.

### P7. 1단계 확인과 인도

대상: 기존 테스트, 작은 네이티브 통합 입력 모음, CURRENT_STATE의 실제 상태 정정.

확인 순서:

1. 코드 작성에 사용하지 않은 저장소 밖 사용자 입력으로 기본 연결을 확인한다. 확보하지 못했으면 그 항목은 미실시로 둔다. 테스트용 생성 모델로 대체해 사용자 입력 확인이라고 쓰지 않는다.
2. 압력·자중, 마찰 접촉, 비선형 재료, 사면체·육면체·셸을 포함하도록 입력을 구성한다. 가능한 조합은 한 모델로 묶되 모두를 하나의 거대 모델에 강제하지 않는다.
3. 네이티브 입력 보존·실행·결과 읽기·ParaView 전달·토론·변경·재실행·저장·재열기를 같은 프로젝트 경로로 확인한다. 각 프로그램을 따로 실행한 결과로 대체하지 않는다.
4. 위 사용자 흐름의 관련 검사와 제품 회귀 검사를 수행한다. 검사 실행·재검사·보고 절차는 루트 AGENTS를 따른다.
5. Windows 실화면의 과거 보류와 이후 실제 FreeCAD·CalculiX·ParaView·전문가 연결 확인을 구분한다. 현재 잔여 부모 전체 조작·재개·IME·창 크기 및 최종 독립 입력은 CURRENT_STATE 종료 표대로 수행한다. 일부 실제 연결·캡처가 통과해도 1단계 전체 또는 GUI 완료로 확대하지 않는다.
6. 2026-10-25 사용자 비판에 따른 부모 화면 재작업은 개별 버튼 수리로 끝내지 않는다. DESIGN §11.3에 따라 처음 진입한 정상·좁은 화면과 프로그램 추가→연결→파일/연결 수정→해제·제거→저장·재열기→복원→기존 계산·대화 열기를 함께 확인한다. 파일 없는 연결 대상의 복구는 상위 작업으로 이어져야 하며, 원본·저장 기록 보존과 실패 시 부분 변경 방지를 검사한다. 새 배치의 전체 사용성과 원 비판의 해소를 원 리뷰어가 직접 판단한다.

인도 시 보고할 내용은 변경된 사용자 동작, 남은 결함, 확인한 실행 환경과 입력 범위다. 기능별 수용 보고서·manifest·증거 packet을 추가하지 않는다. 실제 입력·로그·결과는 테스트 또는 프로젝트의 자연스러운 산출물로 남긴다.

## 5. 후속 확장 조건

PDE·설치·RAG 코드와 유효한 검사는 보존하고 본선의 결함은 수정한다. 기존 수치 코드 보존 방침은 2026-10-26 후속 사용자 지시로 대체됐다. numerical 전체·기존 패널·전용 테스트를 폐기하고 독립 MDO를 새로 만드는 범위와 Phase 1–3 종료 조건은 [새 MDO 명세](../specs/spec-clean-slate-mdo-design.md)를 따른다. 이는 과거 P1~P7 판정이나 다른 솔버의 미완료 상태를 변경하지 않는다.

- Code_Aster·OpenCourant: 등록 목록에 이름을 넣는 작업과 실제 네이티브 파일 교환·실행·판독 지원을 구분한다. 기존 GUI에 프로그램 정의와 어댑터를 붙인다.
- 최적화: 새 MDO에서 실제 프로젝트의 변수·응답을 네이티브 변경·JobManager 실행 경로에 연결한다. 직접 run_fn 우회와 기존 구현 shim을 두지 않는다. holdout·실제 재평가의 유효한 검증 조건은 새 테스트로 작성한다.
- PDE: 자체 입력 형식을 유지한다. 구조 FE 공통 모델에 억지로 넣지 않는다. 제품 실행을 노출할 때 같은 작업 관리·결과 참조 계약을 사용한다.
- RAG: 매뉴얼 수와 조각 수 확대는 결과 출처·솔버 제한·오류 표시가 확보된 뒤 한다.
- Windows: 과거 보류는 해제돼 실제 창 연계·경로 일부를 확인했다. CURRENT_STATE의 잔여 실제 부모 조작·재개·화면 크기/배율·IME 조건을 완료한다. 이미 확인한 연계를 미실시로 되돌리거나 일부 통과를 전체 완료로 확대하지 않는다.

## 6. 개발 운영 문서

개발·별도 세션 운영·파일 배정·독립 QA·통합·병합·원격 확인은 [루트 AGENTS.md](../../AGENTS.md)를 따른다. 이 문서는 P1~P7의 구현 범위와 완료 조건만 소유하며 공통 운영 절차와 시작 프롬프트를 복제하지 않는다.

2026-10-23 정리: 이 절의 공통 작업 규칙은 루트 AGENTS로 통합했다. 제품 작업 순서, 단계별 완료 조건, 기존 리뷰 판정과 역사적 수치는 바꾸지 않았다.

## 범용 CAE 재료 연구·이론 자문·프로그램 연동 — 2026-11-12

사용자의 조사와 계획 갱신 요청에 따라 Workbench main `1c1cacb`와 Prep `f40bfea`를 대조했다. DP와 Xia는 예시이며, 목표는 여러 재료 모델의 정의·시험자료 동정·최적화, 일반 CAE 이론과 실제 결과에 대한 자문·검토, 외부 프로그램 연결이다.

새 모델마다 계산식과 계수·필요 입력을 설명하고, 실제 계산과 결과 읽기를 담당할 코드를 등록한다. 공통 최적화나 대화 코드에 모델 이름별 조건문을 계속 추가하지 않는다. 이는 현재 모든 모델을 지원한다는 뜻이 아니다.

아래 항목은 기존 P4·P5·P6와 MDO의 확장 계획이며 **제품에서는 아직 구현하지 않은 후속 작업**이다. 구현 현황은 [CURRENT_STATE](../../CURRENT_STATE.md#사용자-기능-점검--2026-11-12)를 따른다. 별도 유한요소 모델 데이터베이스나 실행 관리기, 범용 전처리기를 새로 만들지 않고 기존 기능을 사용한다.

함수와 데이터 항목, 저장 형식의 버전, 오류 처리, 수치 검사와 파일 담당은 [전체 구현 명세](../specs/spec-cae-research-implementation.md)에 적었다. 이 절은 우선순위와 개발 순서를 설명한다.

### 전체 구현 착수 단위 — 2026-11-12 추가 확정

사람이 읽는 [개발 작업표](../specs/cae-research/IMPLEMENTATION_TASKS_ko.md)와 [공통 기능 명세 C11](../specs/cae-research/core-implementation.md)을 기준으로 나눠 구현한다.

먼저 공통 자료와 단위 처리인 `CORE01`, 시험 비교와 동정 기능인 `CORE02`, 저장·복구인 `STORE01`을 만든다. 재료별 계산 `MAT-A`·`MAT-B`, 질문과 문헌 검색 `E0–E2`, 결과 변환·읽기 `POST01–04`는 담당을 나눠 진행한다. 이후 화면 `UI01`, Prep 적용 `PREP01`, 프로그램 연결 `LINK01`, 실제 AI 자문과 검토 `E4/E5`, 선택적으로 사용할 RP 수정판 연결 `POST05/06`을 실제 사용 과정으로 이어 확인한다.

여러 작업이 쓰는 파일은 편집자를 한 명으로 정한다. 선행 조건과 오류·수치·운영체제별 검사는 작업표를 따른다. 후처리 변환 작업의 기록은 기존 프로젝트 버전 3에 별도 파일로 저장할 수 있다. 새 `material_study` 항목을 처음 저장할 때는 프로젝트 버전 4를 쓰며, 읽기와 다른 이름으로 저장은 버전 1–4를 처리해야 한다. 문서나 작은 계산 예제의 성공을 제품 기능의 완료로 취급하지 않는다.

| 5. P4/P5: RP 후처리 | Workbench가 선택한 결과를 외부 RP에서 열고 원래 해석 결과를 보존한다. | 별도 복사본에서 변환하고 실제 필드값을 검사한다. RP를 띄웠거나 일괄 실행이 종료 코드 0을 반환했다는 이유만으로 계산·후처리를 성공 처리하지 않는다. |
| 6. P5: 독립 자문 검토 | 제안과 별도 검토의 이견, 수정, 근거 부족을 대화 기록에 보존한다. | 같은 시점에 고정한 동일 자료로 별도의 요청과 답변을 실행하고 이유를 저장한다. 역할명만 바꾼 한 답변을 독립 검토로 세지 않는다. 오류와 제한시간 초과는 근거 부족으로 남긴다. 모델 적용과 해석 실행은 사용자의 명시 동작으로 유지한다. |

### 재료 모델링·동정·최적화

공통 기능은 모델의 정확한 식과 출처, 지원 이력, 재료축·응력과 변형률의 정의·단위, 고정하거나 조정하거나 다른 계수에 연계할 변수, 범위와 변환을 다룬다. 시간·변형률·주파수와 하중 이력을 가진 여러 시험을 함께 읽고, 시험별 잔차·가중치와 동정에 쓰지 않을 검증시험을 보존한다.

계산을 실행하고 결과를 모으는 코드에는 실제 계산인지 대리모델 예측인지, 실패·취소·이전 결과 재사용 여부와 출처가 남아야 한다. 입력파일 내보내기와 열린 문서에 적용하기는 분리한다. 이력 의존 시험을 변형률 순서로 정렬해 원래 경로를 잃어서는 안 된다. 솔버별 구성식과 입출력 차이는 해당 연결 코드가 맡는다. 정확한 정의는 [재료 구현 명세](../specs/spec-cae-research-implementation.md#materials)를 따른다.

DP는 LAW10/21/81/102, Abaqus, LS-DYNA 사이에 식·부호·캡·상태방정식·소성 흐름·경화가 어떻게 다른지 구분해야 한다. Xia 2002 원모델은 정확한 문헌과 코드를 따로 식별한다. 이를 LAW112와 동일하다고 한 이전 설명은 정정한다.

첫 구체 후보인 GMN2012 문헌에서 파생한 power XBP는 원 Xia와 다른 명칭·상태·한계를 가진 모델로 정의했다. 두 Ogden 모델, Prony의 시간·온도 변화 관계, NEML 반복 소성, LAW33, DP, 직교이방 모델도 같은 공통 연결 구조를 사용한다. 모델마다 실제 구현과 검증 상태를 따로 표시하며, 목록에 올렸다는 이유만으로 계산 지원을 선언하지 않는다.

공개 솔버의 구성식과 기존 계산 라이브러리를 우선 사용한다. 모든 모델의 자체 재료점 적분기부터 새로 만드는 일을 선행 조건으로 두지 않는다. RAD 고정폭 재료 항목에 INP의 가변 길이 문자열 치환을 그대로 적용하지 않는다.

### 전문가의 자료 조회와 답변 검토

현재 `allowed_tools`는 AI에게 보낼 자료의 종류를 설명하는 설정이다. OpenAI 호환 요청에 실제 함수 호출 도구를 전달하는 기능은 없고, OpenScience의 실행 도구도 비활성이다. Prep MCP가 있다는 사실이 전문가 창의 도구 연결 완료를 뜻하지 않는다.

첫 도구는 기존의 문헌 검색, 선택한 실행·결과 시점의 조회, 지원 재료 항목 검사처럼 읽기만 하는 기능으로 제한한다. 요청과 반환에는 도구 이름·입력값·자료 출처·실행·결과 시점·단위·누락 여부·현재 모델과의 불일치·오류·시간과 호출 횟수·근거 ID를 남긴다.

오래된 결과, 선언되지 않은 단위, 허용 범위 밖의 요청, 문서에 섞인 악성 지시, 취소와 제한시간, 호출 횟수 제한을 검사한다. 실제 AI 연결마다 도구 요청과 결과 반환을 확인해야 하며, 프롬프트에 도구 목록을 적은 것만으로 완료하지 않는다. 프로그램이 미리 자료를 넣어 주는 동작과 AI가 도구를 요청하는 동작도 구분한다.

AI에게 모델 변경, 덱 덮어쓰기, 솔버 실행 명령은 제공하지 않는다.

현재 제안 검토는 출처와 파일 변경 여부의 확인, 사용자 검토다. 독립 CAE 검토에서는 구성식의 가정, 경계조건, 요소·접촉·수렴, 결과 해석의 주장과 실제 원문 지지를 대조해야 한다. 결론은 `pass`(통과), `revise`(수정 필요), `insufficient`(근거 부족)와 이견으로 저장한다.

같은 모델을 서로 다른 요청에서 사용했으면 모델과 요청 ID를 기록하고, 서로 다른 인간 전문가가 검토했다고 표현하지 않는다. 과거의 실제 구독 답변과 이번 환경에서의 모의·검색 검사는 구분한다. 기존 로컬 또는 구독 AI 연결을 사용하고 새 유료 API를 필수 조건으로 만들지 않는다.

### OpenCourantRP 연결 순서

[OpenCourantRP](https://github.com/CAMLAB-UChile/OpenCourantRP) `cec23cb`는 Windows용 해석 실행·후처리 앱이다. 현재 명령줄에는 `--selftest`만 있고 `--project/--results`는 없다. 프로젝트의 `_0000.rad`·`_0001.rad`와 `NAMEA###.vtk`를 찾으므로, 임의의 결과파일 경로를 인자로 넘기면 열린다고 가정하지 않는다.

1. 별도 설치한 앱에서 폴더를 수동 선택하는 경로부터 안내한다. 원래 계산 결과가 보존된 `runs/<id>` 폴더를 직접 넘기지 않는다. RP가 `rp_run`을 다시 쓸 수 있으므로 입력 덱, 상대 INCLUDE와 기존 VTK를 별도 후처리 폴더에 복사하고 원래 실행과 파일 식별값을 연결한다. 수동 사용에서의 재실행 가능성과 후처리 전용 수정판의 Run 비활성화를 구분한다.
2. 같은 실행을 자동으로 여는 인터페이스는 아직 없다. 원 저장소는 PR과 Issues를 받지 않는다고 밝혔으므로 제안만 하고 기다리는 방식에 의존하지 않는다. AGPL 조건을 확인한 별도 수정판의 명령은 `--post-only --handoff <json> --receipt <json>`로 정했다. [후처리 명세](../specs/cae-research/post-implementation.md)대로 구현하고 실제 Windows에서 연다. Workbench의 `JobManager`가 실행한 솔버를 RP가 다시 실행하지 않게 한다. RP의 일괄 실행은 정상 종료 문구가 없어도 종료 코드 0을 반환할 수 있다.
3. 애니메이션 결과를 VTK로 바꿀 때는 실제 변환 프로그램을 실행한다. 형상과 원래 절점·요소·부품 ID, 실제 시간, 응력·변형률 성분, 쉘 두께 위치, 요소의 로컬축·전역축·부호·단위를 다른 계산 기준과 비교한 뒤 결과로 등록한다. 파일이나 PVD 목록이 있다는 사실만으로 원 결과를 정확히 읽었다고 표시하지 않는다.
4. 재료의 직교축은 요소 로컬축과 별도로 확인한다. RP의 단위 설정은 표시 선언이며 수치 자체를 환산하는 기능으로 해석하지 않는다. 실행용 사본에서 `/H3D`를 제거한 경우 원래 덱과 구분한다.
5. RP는 독립 후처리 프로그램으로 유지하고 Workbench가 실행·상태·결과 연결을 관리한다. 솔버 실행파일을 바로 동봉하지 않고 별도 설치 경로를 먼저 사용한다. AGPLv3와 동봉 의존성의 배포 조건, 새 Windows 설치, 한글·공백 경로, 취소·오류·원본 보존을 확인한 뒤 해당 연결을 완료 처리한다.

이 계획은 재료식 혼동, 시험자료 전처리, 결과 없는 이론 질문, 검색 결과와 근거 충분성의 구분, RP의 원본 변경과 솔버 중복 실행에 대한 비판을 반영했다. 문서 반영이나 PR 병합을 실제 기능 또는 전문가·RP 연결 검증의 완료로 보고하지 않는다.

### 다른 세션의 GUI 자산·자동화 제안 통합

공용 GUI 자산 조사에서 제안한 디자인 토큰/아이콘, 단위·속성·곡선·트리 위젯, 공유 Action·Undo·선택·문서·도킹 구조를 CAELab Prep의 실제 편집 흐름에 적용한다. 필요한 부품부터 내부 모듈로 분리하며 별도 범용 프레임워크나 새 저장소 제작을 전처리기 개발의 선행 목표로 삼지 않는다. 이 워크벤치의 제품 역할은 기존 DESIGN대로 유지한다.

[PrePoMax 3.0 공식 발표](https://prepomax.fs.um.si/version-3-0-0/)에 Python 스크립트/API 도움말·명령 기록 변환·MCP 서버 지원이 명시돼 있다. 현재 PR #51의 수동 PMX 재열기·INP 출력 연결을 기반으로 **Windows 실제 파일 흐름 확인 → Python을 통한 반복 전처리 자동화 → MCP 세션 보조 평가** 순서로 진행한다. 문서에 기능이 있다는 사실을 실행·연동 검증으로 보고하지 않는다. 워크벤치에서 시작한 솔버 계산은 JobManager가 소유하며 외부 전처리기의 자동화가 계산을 중복 시작하지 않게 한다. 이 후속 자동화는 아직 구현하지 않았다.
