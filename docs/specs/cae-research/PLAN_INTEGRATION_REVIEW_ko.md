# 기존 개발 계획과 구현 명세의 추가 검토 결과

2026년 11월 12일, 기존 계획·진도표와 새 구현 명세를 함께 다시 검토했습니다. 새 12개 작업을 별도 전체 계획으로 운영하지 않고 [기존 Workbench 계획](../../review/2026-10-23-codex-improvement-plan.md#plan-integration) 아래에 연결했습니다. Prep의 기존 단계와 N01–N26 현황도 유지합니다.

## 참여자와 실제 토론 방법

이전 작업에 참여했던 서브에이전트 8명을 다시 불러 순차 검토했습니다. 외부 인간 전문가를 섭외했다는 뜻은 아닙니다.

| 참여자 | 이번 책임 |
|---|---|
| Workbench 계획 감사자 | 기존 7단계·작업 분담·완료 기준과 새 작업의 연결을 검토했습니다. |
| Prep 계획 감사자 | 기존 단계·진도·공용 부품·문서 적용과 남은 요구를 대조했습니다. |
| 재료 명세 작성자 | 재료별 계산·동정·검증 조건과 실제 코드 연결을 보완했습니다. |
| 전문가·후처리 명세 작성자 | 이론 자문·자료 조회·별도 심의·RP 연결을 보완했습니다. |
| 독립 기술 검토자 | 실제 코드·상태·수치·저장·동시 실행의 모순을 지적하고 수정본을 확인했습니다. |
| 독립 한국어 검토자 | 사용자 설명과 명세의 문장·용어·띄어쓰기·완료 표현을 검토했습니다. |
| 앞선 RAG 검토자 | 역할별 권한·수치 인용·질문별 검색 판정의 빈칸을 추가 검토했습니다. |
| 앞선 재료 검토자 | 프로필별 조건·역문제 시험·GEOS 실행·보류 시험의 빈칸을 추가 검토했습니다. |

[공유 ASCII 원장](plan-integration-debate-ascii.jsonl)에 각 참여자가 직접 발언을 썼습니다. 정해진 다음 작성자만 앞선 파일을 읽고 추가할 수 있고, 이전 파일의 바이트 확인값과 실제 검토한 문서의 확인값을 남깁니다. 통합 담당이 발언권을 넘기며 덮어쓰기와 동시 작성을 막았습니다. 추가 참여자의 발언 순서도 이전 내용을 바꾸지 않고 통합 담당의 발언으로 연장했습니다.

각 지적은 근거를 대조해 토론하고, 반박할 근거가 없으면 수용해 고쳤습니다. 수정한 실제 문서는 원 지적자가 다시 읽고 종결했습니다. 작성자의 완료 선언이나 다른 사람의 동의로 원 지적을 닫지 않았습니다. 최종 판단과 그 범위는 원장의 각 작성자 발언에 있습니다. 이 기록은 공개 가능한 기술 토론이며 모델의 비공개 내부 추론 기록이 아닙니다.

## 무엇을 보완했는지

| 발견한 부족한 부분 | 반영한 변경 |
|---|---|
| 새 작업과 기존 계획의 연결이 포괄적인 설명에 머물렀습니다. | 12개 작업마다 기존 WB/Prep 항목, 재사용할 코드, 추가 개발분과 완료 영향을 연결했습니다. 기존 현황과 새 작업 수를 더해 진행률을 만들지 않습니다. |
| 선행 조건 한 칸에 설계 합의·코드 준비·최종 확인이 섞였습니다. | 세 조건을 나누고, 이론 질문·해석식 계산·화면 개발 등 독립 작업이 불필요하게 서로를 기다리지 않도록 했습니다. |
| 기존 작업과 새 작업의 우선순위·담당이 모호했습니다. | 같은 사용자 경로의 오류·자료 손실·회귀를 먼저 고치고 기존 진행 작업을 승계합니다. 파일별 한 명 편집을 명시하고 미래 구현자·검토자·납기는 미정으로 표시했습니다. |
| 명세마다 다른 구현 파일명이나 창 호스트 이름을 지시했습니다. | 재료별 명세의 정확한 파일명과 공통 계약·목록·Prep 인계를 맞췄습니다. |
| 중지·취소와 긴 계산 중 잠금의 의미가 불명확했습니다. | 활성 작업 ID를 먼저 공개하고 상태 잠금은 짧게 사용합니다. 중지는 이미 배정한 후보의 필수 시험을 마치는 경계, 취소는 즉시 요청 응답과 후속 종료 확인으로 나눴습니다. |
| 캐시 결과로 최종 확인을 대신하거나 보류 시험이 계수 선택에 섞일 수 있었습니다. | 탐색과 최종 확인을 분리했습니다. 선택을 먼저 고정하고 최종 확인은 새 실제 계산으로 수행합니다. 보류 결과 노출 이력을 저장하고 저장 실패 시 결과 전달을 막습니다. |
| 재료 이름·평가식은 있으나 역으로 계수를 찾는 검사 조건이 부족했습니다. | 프로필별 필요한 정보, 자유·고정 계수, 시작값, 자료 격자·분할·가중치, 예산·오차 기준을 보완했습니다. Prony 항 수 비교와 검증자료 사용도 고정했습니다. 합성 회귀 목표와 실제 재료 검증을 구분합니다. |
| GEOS를 기존 실행기에 연결한다는 말만으로 구현 경로가 충분하지 않았습니다. | 프로그램 발견·등록, XML 입력 사본, 실행 명령, 텍스트 결과 수집, 실행 후 입력 무결성 확인을 기존 확장 지점에 연결했습니다. 탄성·소성 상태 검사도 바로잡았습니다. |
| 문서 적용이 미지원이면 솔버 덱 내보내기는 가능한 것처럼 읽혔습니다. | 계산·동정·FE 재평가·솔버 덱 출력·열린 문서 적용을 각각 판정합니다. 덱 출력 구현도 없는 모델에는 계수·평가 보고서만 제공합니다. |
| 기존 전문가 이슈와 새 자문 기능이 따로 관리될 수 있었습니다. | 이슈 #45의 남은 동작을 같은 전문가 창·요청 수명 검사에 승계하고, 기존 수정은 재사용하며 원 이슈의 종료 조건을 유지합니다. |
| 역할별 자료 제한이 새 도구에서 빠지거나 실제 수치의 인용 경로가 불분명했습니다. | 실제 도구·이력·검토에도 자료 권한을 검사합니다. 수치는 원파일·선택·단위·실행/평가에 연결한 호스트 인용으로 검토하고, 생성 문장으로 수치의 진위를 증명하지 않습니다. |
| 검색 후보가 나왔다는 사실과 질문의 근거가 충분하다는 판단이 섞였습니다. | 출처 검토와 새 질문의 관련성 판정을 분리하고 실제 판단 요청·입출력·예산을 명세했습니다. 평가 정답표를 제품 실행에 사용하지 않습니다. |
| 첫 모델·몇 가지 참조 계산을 전체 완료로 오해할 수 있었습니다. | 첫 사용자 흐름, 정확한 11개 프로필, 새 12개 기능의 연결, 기존 두 제품 전체 납품을 각각 판정합니다. 기존 8제품·메셔·대용량·Windows 잔여를 유지합니다. |

## 검사와 완료 표현

문서 검사에서는 파일 목록의 실제 바이트, JSON·Python 구문, 12개 작업 ID·참조·선행 순환·구현 파일명, 토론의 작성 순서·바이트 연결·참여자별 종결 판단을 확인합니다. 상대 문서 링크와 변경 내역도 검사합니다. 관련 검사는 [check_handoff.py](check_handoff.py)에 있으며 최종 토론이 끝나지 않았거나 원 지적이 남으면 통과하지 않게 했습니다.

이번 변경은 개발 계획과 구현 명세의 보완입니다. 새 재료 서비스·창·실제 AI 도구 연결·새 Prep 적용·RP 자동 연결의 제품 구현을 완료했다는 보고가 아닙니다. 과거 수치 실행과 이번 문서 검사를 합산하지 않습니다. 정확한 현재 구현은 각 저장소 CURRENT_STATE와 [사용자용 현황](USER_PROGRESS_ko.md)을 따릅니다.

별도 간트 `CAELAB_PROJECT_BIG_PICTURE`는 존재·과거 열람 기록을 찾았지만 원본을 확보하지 못했습니다. 원래 달력 일정까지 갱신했다고 표시하지 않았으며, 현재 확인한 기존 계획에 개발 순서·병렬 조건·인수 조건을 반영했습니다. 실제 구현 인력과 날짜를 수락하면 같은 작업 행에 넣도록 했습니다.
