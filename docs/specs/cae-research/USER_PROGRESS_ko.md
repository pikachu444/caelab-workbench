# CAELab 개발 현황 — 사용자용 설명

현재 개발 순서는 [전체 개발 계획](../../review/2026-10-23-codex-improvement-plan.md#execution-order), 실제 맡길 작업은 [전체 실행 목록](IMPLEMENTATION_TASKS_ko.md#whole-backlog)에서 확인합니다. 첫 Prony 동정·저장·재열기 이후 11개 재료 프로필, 실제 자문·별도 심의·RP 및 기존 전처리·플랫폼 잔여까지 계속합니다. 이번 갱신은 개발 순서의 구체화이며 새 제품 기능 구현은 아닙니다.

이번 계획 통합에서 발견한 문제와 수정·검토 방법은 [추가 검토 결과](PLAN_INTEGRATION_REVIEW_ko.md)에 정리했습니다.

작성일: 2026년 11월 12일

**재료 모델을 시험자료에 맞추는 기능, 전문가에게 질문하고 검토받는 기능, OpenCourantRP로 결과를 보는 기능을 어떻게 개발할지 정리했습니다. 일부 계산 방법은 실제로 시험했습니다. 이 기능들이 프로그램 화면에서 모두 연결되어 작동하는 단계까지 개발한 것은 아닙니다.**

## 기존 계획·진도표와 어떻게 합쳤는지

기존 Workbench의 7단계 계획과 Prep의 단계별 계획·26개 현황 항목에 새 12개 세부 작업을 연결했습니다. 각 작업에 기존에 있는 코드, 추가로 만들 부분, 필요한 담당 역할, 먼저 합의할 형식, 실제로 필요한 코드, 끝났다고 판단할 조건을 적었습니다. 기존 전문가 이슈 #45와 Windows·메셔 등 남은 작업도 유지했습니다.

실제 제품 구현 담당과 납기는 아직 미정입니다. 새 기능의 구현 상태도 모두 예정입니다. 이전 간트의 존재 기록은 확인했지만 원본을 확보하지 못했으므로 달력 일정까지 이행했다고 보고하지 않습니다. 현재 확인 가능한 개발 순서와 병렬 조건은 [기존 전체 계획](../../review/2026-10-23-codex-improvement-plan.md#plan-integration)에 반영했습니다.

이번 재검토에서는 구현 파일명 불일치, 중지·취소의 처리 범위, 캐시를 쓰지 않는 최종 재계산, 문서 적용과 솔버 내보내기의 지원 차이도 보완했습니다. [실제 회의 기록](plan-integration-debate-ascii.jsonl)은 각 참여자가 순서대로 직접 작성했습니다.

## 무엇을 했는지

기존 Prep과 Workbench의 코드, 외부 프로그램과 재료 모델의 원문 자료를 조사했습니다. 이를 바탕으로 어떤 기능을 추가하고, 기존 기능과 어떻게 연결하며, 무엇을 확인해야 개발이 끝났다고 할지 명세서에 적었습니다.

계산 방법도 일부 시험했습니다. 예를 들어 OpenCourant로 작은 발포체 모델을 계산했고, 점탄성 모델의 계수를 자동으로 조정해 가상 시험곡선에 맞추는 계산을 실행했습니다. 프로그램의 새 화면에서 사용자가 처음부터 끝까지 수행한 시험과는 구분해야 합니다.

## 기존 기능과 앞으로 개발할 기능

| 작업 | 기존 코드에 있는 기능 | 이번에 개발 방법을 정한 기능 |
|---|---|---|
| 해석 모델 작성 | Prep의 해석 입력파일 편집, 일부 재료·조건·곡선·메시 편집, 저장과 실행 취소 기능이 있습니다. 모든 재료와 입력 항목을 지원하는 것은 아닙니다. | 시험자료로 구한 계수와 곡선을 열린 Prep 모델에 반영하고, 한 번의 실행 취소로 되돌리는 기능입니다. |
| 해석 실행 | Workbench에는 입력파일을 솔버에 넘기고 실행 상태와 결과를 관리하는 기능이 있습니다. | 계수를 바꿀 때마다 필요한 해석을 실행하고, 그 결과를 시험곡선과 비교하는 기능입니다. |
| 재료 계수 동정 | 기존 최적화 도구와 해석변수·스칼라 결과를 다루는 기능이 있습니다. | 여러 시험자료를 함께 읽고, 고정할 계수와 조정할 계수를 선택하고, 계수를 찾은 뒤 별도의 시험으로 확인하는 재료 연구 기능입니다. 이를 위한 새 화면은 아직 구현하지 않았습니다. |
| 전문가 자문과 검토 | 대화와 자료 전달에 쓰는 기존 코드가 있습니다. | AI가 문헌이나 실제 해석 결과를 찾아 읽고 답변하며, 별도의 검토 요청으로 가정·근거·결론을 확인하는 기능입니다. 이 전체 흐름을 실제 AI와 연결해 검증하는 작업이 남아 있습니다. |
| OpenCourantRP 후처리 | OpenCourantRP는 별도 프로그램으로 사용할 수 있습니다. | Workbench에서 선택한 해석의 정확한 결과를 RP에서 열고, 원래 해석을 다시 실행하거나 덮어쓰지 않도록 연결하는 기능입니다. 이 자동 연결은 아직 구현하지 않았습니다. |

Prep의 모델 편집 기능이나 Workbench의 솔버 실행 기능이 이미 있다는 사실만으로, 위의 새 재료 연구·자문·후처리 연결이 완성됐다고 볼 수는 없습니다.

## 실제로 실행해 본 계산

### 발포체 모델 계산

공식 Linux용 OpenCourant를 사용해 LAW33의 한 설정인 Ka1로 작은 발포체 시험모델을 계산했습니다.

계산 시간간격을 두 수준으로 줄여 결과를 비교했습니다. 응력과 변형, 밀도·체적 등의 결과가 제대로 전달되는지 확인했고, 별도로 작성한 재료 계산식의 결과와도 비교했습니다. 정해 둔 오차 기준을 통과했습니다.

이 시험으로 확인한 것은 해당 작은 모델과 계산 조건입니다. 모든 발포체 조건, 전체 제품 모델, Windows 화면에서의 사용까지 검증한 것은 아닙니다.

### 점탄성 계수 동정

미리 정한 계수로 가상 시험곡선을 만든 뒤, pyvisco와 Workbench의 기존 최적화 계산을 이용해 곡선을 맞췄습니다.

계수를 찾는 데 사용한 곡선뿐 아니라, 계수를 찾을 때 쓰지 않은 별도의 곡선과도 비교했습니다. 두 경우 모두 계산곡선이 가상 시험곡선과 거의 일치했습니다.

이는 계산과 최적화 연결을 확인한 시험입니다. 실제 재료의 인장시험이나 DMA 자료와 맞는지는 아직 검증하지 않았습니다.

### 다른 계산과 실행하지 못한 항목

초탄성 모델에서는 체적변형을 허용할 때의 횡방향 변형 계산과 수치해 선택을 검사했습니다. 최적화의 제약조건 처리도 확인했습니다.

반복 소성 계산에 쓸 NEML 라이브러리는 필요한 실행 환경을 갖추지 못했습니다. NEML을 이용한 실제 계산은 통과로 처리하지 않았습니다.

후처리 담당이 이번 재실행에서 수행한 작업은 시험용 해석 입력파일 생성까지입니다. 후처리 관련 계산을 모두 다시 실행했다고 보고한 것은 아닙니다.

## 어떤 재료 모델을 대상으로 설계했는지

DP와 Xia는 사용자가 든 예시입니다. 개발 방법을 정리한 범위에는 다음 재료군도 포함됩니다.

| 재료군 | 명세서에 정리한 내용 | 현재 알아야 할 한계 |
|---|---|---|
| Drucker–Prager 소성 | 사용할 식, 경화와 소성 흐름, 시험 조건, 계수 동정 방법을 구분했습니다. | DP라는 이름으로 모든 변형 모델을 한꺼번에 지원하지 않습니다. GEOS를 이용하는 실행 경로는 Linux용으로 정했고, Windows용 별도 계산 경로도 명시했습니다. |
| 발포체 | OpenCourant LAW33의 Ka0와 Ka1에 대해 계산식, 계수, 이력과 필요한 결과를 정리했습니다. | 위의 작은 Ka1 모델 시험이 모든 속도·유지하중·전단 조건의 검증을 대신하지 않습니다. |
| 직교이방 재료와 종이 | 방향별 탄성 모델과 문헌에서 파생한 탄소성 모델을 구체화했습니다. | 파생 모델을 원래 Xia 모델이나 LAW112와 같은 모델이라고 표시하지 않습니다. 원 Xia 모델 전체의 지원은 완료되지 않았습니다. |
| 초탄성 | 비압축성 Ogden 모델과 압축성을 허용하는 Ogden 모델을 구분했습니다. | 체적변형과 안정성 조건을 별도로 확인해야 합니다. |
| 점탄성 | Prony 급수와 온도에 따른 시간 변화 관계를 다루도록 설계했습니다. | 실제 재료시험에 맞는지는 별도의 검증이 필요합니다. |
| 반복 소성 | NEML의 Chaboche 모델을 이용하는 방법을 정리했습니다. | NEML을 이용한 실제 실행 확인이 남아 있습니다. |
| 변형률 속도·온도·파손 개시 | 주어진 상태에서 Johnson–Cook 식으로 유동응력과 파손 개시를 계산하는 방법을 정리했습니다. | 손상 진전, 요소 삭제, 유한요소 응력 적분까지 구현한 기능은 아닙니다. |

이 표는 **앞으로 구현할 모델과 확인할 조건**을 설명합니다. 현재 프로그램에서 모두 선택해 사용할 수 있다는 지원 목록은 아닙니다.

새 모델을 추가할 때도 계산식, 계수, 필요한 시험자료, 실제 계산 프로그램, 결과 읽기, 검증 방법을 갖춰야 합니다. 이름만 목록에 넣어 최적화 기능이 생기는 것은 아닙니다.
