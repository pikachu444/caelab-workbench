# E 독립 검토 — 새로 재구성한 구현 명세

> 이 문서는 작성 당시 검토 범위와 판정을 보존합니다. 2026-11-12의 추가 계획 통합은 [기존 전체 계획](../../review/2026-10-23-codex-improvement-plan.md#plan-integration)과 [새 실제 토론 기록](plan-integration-debate-ascii.jsonl)을 따릅니다. 과거 승인을 바뀐 모든 문서나 제품 구현의 승인으로 확대하지 않습니다.

이 문서는 기존 검토 결과의 한국어 편집본이며, 당시 검토 대상과 결론을 보존합니다. 작성일은 2026-11-12이며 검토자는 독립 검토 역할 E입니다. 환경 단절 뒤 실제 Git blob을 읽고 새로 작성한 검토입니다. 회수하지 못한 원래 R4 파일이나 원래 토의 순번 18이 아닙니다.

## 판정과 정확한 검토 대상

**선택 범위의 정적 구현 명세를 승인합니다. E가 제기한 미해결 차단 문제는 0개입니다.** 본문과 부속 명세는 구현자가 다시 결정해야 했던 공용 구현 규칙, 운영체제 지원, 저장 소유자, 답변 검토의 통신 형식을 구체적으로 고정했습니다. 제품 서비스·GUI·솔버 기능·대규모 언어 모델(LLM)·Windows의 구현 또는 실행 완료를 승인한 것은 아닙니다. 새 참조 코드의 Python·솔버 자동 검사 결과는 별도의 실행기록을 근거로 판단합니다.

직접 읽은 Workbench 통합 후보 커밋은 `98be90bfe1d8d02ae099bc0aecf84d1d11110218`입니다. 실제 파일을 `fetch_file`로 다시 읽어 아래 6개 명세와 README·CURRENT_STATE·기존 계획·최신 C 평가 자료의 Git blob이 검토본과 같음을 확인했습니다. `fetch_commit`의 변경 경로 65개는 문서·참조 자산·검증 작업 흐름이었고 제품 app/caelab 코드는 변경 0개였습니다. 후보 이후 추가된 검토 보고서·토의·실행기록은 root의 최종 묶음 검사 대상입니다. 당시 후보에 이미 있었다고 소급하지 않습니다.

## 복구본에서 새로 찾은 오류와 직접 재검사

원래 지적을 닫았다는 이유만으로 새 자산을 승인하지 않았습니다.

- **E-RC1:** C 참조 파서는 `__proto__` 추가 키, 상속된 인용 `toString`, RFC JSON 공백이 아닌 NBSP, UTF-8 45040바이트의 한국어 action을 허용했습니다. 작성자는 프로토타입 없는 객체·자기 속성 검사·RFC 공백·UTF8 32768바이트 상한으로 수정했습니다. 새 `b43ec55993945393838ce95872add96e10dfa4b7`에서 E가 같은 반례 4개를 재실행해 모두 거부함을 확인했습니다. 기존 부정 검토 사례 8개, 정상 최종 답변의 `not_assessed`, 정상 검토 통과, 중대 지적의 수정 요청, 재심 연결 누락 시 이벤트 0건도 확인했습니다. 기계적인 통신 형식 검사이며 답변 의미의 정답을 보증하지 않습니다.
- **E-RC2:** 공통 문서의 전체 상태값 문장과 `constraint_status` 대문자 값이 충돌하고 무차원 단위 문자열이 모호했습니다. 필드별 정확한 상태값과 `unit=""`로 수정한 `f78a...` 이후 최종 공통 문서에서도 이를 확인했습니다.
- **E-RC3:** 재구성 중 축약된 부모·`RunStore`의 비차단 저장 잠금과 보류 연결 기록을 다시 고정했습니다. 최종 C8/D5에는 불변 이벤트, 재열기·대조 조정 시 CAS와 충돌 유지, 모든 잠금 대기시간 0, 유휴 쓰기 소유자 제한이 있습니다.
- **E-RC4:** `EvidenceEnvelope`의 이름과 `kind=result`를 후속 구현자가 정하도록 남긴 문장을 거부했습니다. 최종 C1은 정확한 바깥 필드·`kind`, `native_run` / `manual` / `calibration` / `document_chunk` 본문, `provenance.artifact_owners`, `availability`, 과거 설명자 포장 형식을 고정합니다. 통합 본문·C·D는 같은 기준을 사용합니다.
- **E-RC5:** C의 후속 답변 시험자료는 새 답변을 가리키면서 이전 답변의 주장 범위·검토 범위 해시·개수를 복사했습니다. 새 `4c6bbb9c274c914ec7976cd5af9d0b59e480bc2b`를 실제 읽고 재계산했습니다. 새 답변은 98코드포인트·비공백 80개였습니다. 답변·요청·자료 묶음 해시와 표준 바이트, 호스트 구간, 연결 코드가 만든 전체 검토자 기록이 정확히 일치했으며 원래 이벤트·연결 문맥은 보존됐습니다. `request_context_hash`와 `evidence_pack_hash`도 구분했습니다.

E의 실행기록은 `recovery_check_receipt.json` — blob `f0be6fa69051a2cee38c6187972343b615071ddc` — 과 `recovery_followup_check.json` — blob `f195445e9ed537d557f309d4023d7f0fcc94ee6c` — 입니다. 새로 실제 실행한 JS를 기록했으며 원래 Python 로그를 복원한 것은 아닙니다.
