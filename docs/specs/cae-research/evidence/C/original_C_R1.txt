C R1: 사용자 전체 요구의 독립 해석

요구의 출발점은 CAELab Prep과 Workbench를 사용자가 실제로 무엇에 쓸 수 있는지 검증하고, 부족한 연결을 개발자가 곧바로 구현할 수 있게 명세하는 일이다. U1의 DP와 Xia는 재료 모델 다양성의 예시이지 제품 범위를 두 모델로 제한하는 주문이 아니다. U7과 U8은 J2 같은 쉬운 예제 하나나 임의 매개변수 치환을 일반 재료 모델링·최적화 능력으로 포장하지 말라는 재확인이다. 따라서 압력 의존, 이방성, 유한변형, 시간·이력 의존, 손상 등 서로 다른 물리적 요구를 실제 솔버·오픈 소스의 구현과 시험 관측량으로 대조하고, 선정 프로필의 직접 구현 경로와 향후 모델의 확장 계약을 모두 남겨야 한다. 변수 수나 카드 지원 목록만 늘리면 충분하지 않다. 시험 데이터, 단위·부호·상태량, 목적함수·제약, 식별 가능성, 검증과 실패 판정이 연결되어야 한다.

Prep은 재사용 CAE 자산과 native RAD 편집·저장·출력을 소유하고 Workbench는 독립 프로그램의 파일 전달·실행·결과와 연구 토론을 연결한다. 소스가 있다는 사실, 프로그램을 등록했다는 사실, 정상 종료했다는 사실과 물리적으로 읽을 수 있는 결과를 얻었다는 사실은 다르다. OpenCourantRP 조사는 URL 소개로 끝낼 수 없다. 고정 개정의 reader·출력 필드·프레임·단위·호출 방식과 라이선스를 확인하여 실제 Radioss/OpenCourant 결과에서 원본을 보존하며 ParaView 또는 경량 판독으로 전달하는 경로와 막힌 지점을 구체화해야 한다. 새 통합 FE 모델이나 중복 큐를 도입해서 이 책임을 흐리면 제품 정의를 위반한다.

전문가 기능은 실제 공급자 호출뿐 아니라 공학 이론·모델링 판단·해석 실행 문제·재료 선택·시험 설계까지 다루어야 한다. RAG 이름만 붙이거나 미리 첨부한 문자열을 한 번 프롬프트에 넣는 것으로 읽기 도구 호출과 후속 심의가 구현됐다고 볼 수 없다. 선택된 native 입력·로그·결과와 솔버 버전에 맞는 원문을 검색·조회하고, 요청된 도구를 실제 실행하여 그 결과를 같은 대화의 공급자에게 돌려주며, 인용과 자료 없음·오류·불일치를 구분해야 한다. 자문·심의의 판정 근거와 반론은 새 실행이 붙어도 유지되어야 한다. 제안은 실행이나 모델 변경 권한이 아니며 사용자의 적용과 재실행 명령을 거친 후 새 결과로 후속 판단해야 한다. 로컬 또는 기존 구독 공급자를 사용할 수 있어야 하고, 유료 API나 새 DB를 필수로 만들어서는 안 된다.

U2–U6와 U9의 핵심은 부족하다는 진단을 반복하는 대신 실제 구현 인계를 완성하고, 독립 참가자가 원요구 전체를 이해한 뒤 근거 있는 반박과 수정을 공개 기록으로 남기라는 것이다. 진행자가 정한 축소 과업만 재진술하거나 형식적인 동의를 모으면 이 요구를 충족하지 못한다. ASCII 기록의 순서·작성자·해시·비판 ID는 재현 가능한 토의 증거이지만 백엔드 모델 정체나 비공개 추론량을 증명하지 않으므로 관측한 사실만 보고해야 한다.

이번 인도의 완료 기준은 각 선정 기능에 고정 소스와 라이선스, 함수·파일/API 경계, 데이터와 저장 스키마, 상태 전이·오류, GUI 사용자 동작, 실제 입력·예상 산출물·수치 허용오차가 마련되고 독립 비판자가 정확히 수정된 결과를 재검토하는 것이다. 전문가 분야에서는 실사용 corpus와 한영 검색 정책, 공급자별 tool 왕복, 중단·저장·재개 및 재실행 후 심의 흐름을 수락 fixture로 고정해야 한다. 명세·fixture 작성 완료와 아직 수행하지 않은 Windows·실솔버·실공급자 runtime 수락을 별도 상태로 남긴다. 작성된 문서가 제품 구현 완료라는 주장은 하지 않는다.
