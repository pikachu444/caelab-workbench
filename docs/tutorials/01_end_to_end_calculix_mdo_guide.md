# 실제 CalculiX 덱으로 시작하는 MDO 가이드

이 안내는 100×20 mm 인장판의 **두께**를 바꾸면서 CalculiX로 질량·변위·응력을 계산하는 작은 연결 실습입니다. GE 산업 모델이나 상용 솔버 비교가 아닙니다. 처음부터 끝까지 입력과 결과를 보존하고, 계산한 표본에서 후보를 선택해 INP에 적용합니다.

## 1. 환경과 완전한 입력 준비

저장소 루트에서 PowerShell을 엽니다. [README](../../README.md)의 Python 의존성을 설치하고, 설치된 CalculiX 실행 파일의 실제 경로를 지정합니다.

```powershell
$env:CAELAB_CCX = 'C:\실제설치경로\ccx.exe'
Test-Path -LiteralPath $env:CAELAB_CCX
$caseDir = Join-Path $env:USERPROFILE 'caelab-tension-tutorial'
New-Item -ItemType Directory -Force $caseDir
Copy-Item docs/tutorials/assets/tension_plate_template.inp $caseDir
python -m apps.workbench_qt.mdo_studio
```

`Test-Path`가 `True`여야 합니다. 예시 경로를 그대로 사용하지 마세요. 재실행할 때는 기존 적용 파일을 덮어쓰지 않도록 새 실습 폴더를 사용합니다. 파일 이름의 공백을 임의로 제거하거나 다른 형식의 덱으로 대체할 필요는 없습니다.

[완전한 입력 파일](assets/tension_plate_template.inp)을 텍스트 편집기로 확인합니다. `...`로 생략된 내용은 없습니다. `<THICKNESS>`는 CalculiX 자체 문법이 아닌 MDO 치환 토큰이므로, 이 템플릿을 ccx에 바로 넘기지 않습니다.

- 4개 S4 셸 요소, 입력 절점 10개, 길이 100 mm·폭 20 mm. CalculiX가 셸을 내부 3D 요소로 확장한 결과에는 20절점이 나타납니다.
- 탄성계수 210000 N/mm², 포아송비 0.3, 밀도 `7.85e-9 tonne/mm³`. 일관 단위는 mm–N–s이며 질량은 tonne입니다.
- x=0의 두 절점은 x방향 구속, 절점 1은 y방향 구속, 판 전체는 면외 이동/회전 구속입니다. 폭 방향 수축을 허용한 순수 인장 연결 사례입니다.
- 반대 끝 두 절점에 각각 +500 N, 합계 +1000 N의 x방향 힘을 줍니다. `FIX`에는 외력이 없습니다.
- `*SHELL SECTION` 다음의 `<THICKNESS>`만 바뀝니다. 셸 두께의 실제 물리 입력 변경이며 외부 CAD 재생성이나 솔리드 필렛 재메시를 시연하지 않습니다.
- `*NODE FILE`의 U, `*EL FILE`의 S, `*NODE PRINT`의 RF, `*EL PRINT`의 EMAS/EVOL을 요청합니다. 누락된 출력을 0으로 채우지 않습니다.

## 2. 덱과 변수·목적·제약 바인딩

1. 빈 MDO Studio에서 **해석 덱 열기**를 누르고 실습 폴더의 `tension_plate_template.inp`를 엽니다. GE 예제 로드는 이 절차에 사용하지 않습니다.
2. 상태바에서 THICKNESS 토큰 감지를 확인하고 **Configure Study**를 엽니다.
3. 변수 표의 `THICKNESS` 행을 다음과 같이 입력합니다.

| Lower | Upper | Initial | Unit |
|---:|---:|---:|---|
| 1 | 3 | 2 | `mm` |

4. 응답 표를 다음과 같이 설정합니다. 목적을 지정하지 않는 응답은 Objective를 비워 둡니다. Unit은 수치 환산 명령이 아니라 덱의 단위 선언입니다.

| Response | Unit | Objective | Constraint | Limit | 출처 |
|---|---|---|---|---:|---|
| `mass_eall` | `N*s**2/mm` | MIN | 없음 | — | DAT의 EALL 집합 총질량(EMAS), tonne와 동등 |
| `disp` | `mm` | MIN | UPPER | 0.02 | 마지막 FRD 프레임의 절점 변위 크기 최댓값 |
| `stress` | `N/mm**2` | 없음 | UPPER | 40 | 같은 프레임의 절점 외삽·평균 응력에서 계산한 von Mises 최댓값 |

5. 설정을 적용합니다. 제약값은 실습용 선택입니다. 재료 인증 허용값이나 실제 부품의 안전기준이 아닙니다.

질량과 변위는 두께 증가에 따라 반대 방향으로 변하므로 다목적 절충이 생깁니다. kg로 읽으려면 tonne 값에 1000을 곱합니다. 단위 칸을 `kg`로 바꾸는 것만으로 이 환산이 수행되지는 않습니다.

## 3. DoE 생성과 실제 배치 실행

1. **Generate DoE**를 누릅니다. LHS 표본 수 `8`, seed `42`를 입력합니다. 기준값 두께 2 mm의 baseline과 LHS 8점, 합계 9행이 생깁니다.
2. 실행 전 행은 `PENDING`이며 응답값은 없습니다. **Run Evaluations**를 누릅니다. 실제 ccx가 백그라운드에서 설계점마다 바인딩한 입력을 계산합니다.
3. 상태바의 진행 수와 표의 완료·실패 상태를 확인합니다. 화면의 진행률은 배치 완료율이며 비선형 잔차 수렴 곡선이 아닙니다. 이 선형 정적 실습에는 반복 최적화 세대별 수렴도 없습니다.
4. 선택점의 실행 ID와 폴더를 확인합니다. 원본 덱 옆 `.caelab_mdo` 아래 실행별 `model.inp`, `model.frd`, `model.dat`, `job.log`와 실행 기록을 보존합니다. 원본 템플릿은 이 단계에서 바뀌지 않습니다.
5. `COMPLETED`와 `FEASIBLE`을 구별합니다. 계산이 끝나도 응력 40 MPa 또는 변위 0.02 mm 제약을 넘으면 유효 후보가 아닙니다. 필수 응답이 없거나 비유한 수치이면 실패 원인을 확인하고 덱의 출력 요청을 수정한 뒤 새 연구로 다시 계산합니다.

**Stop Scheduling**은 현재 배치를 중지합니다. 취소된 점은 완료·Pareto 후보로 세지 않습니다. 다른 덱 열기·연구 설정·원본 적용은 진행 중인 계산이 끝난 뒤 수행합니다. 실제 걸린 시간은 머신·코어·부하에 따라 달라지며 이 안내에는 보장 시간이나 속도 향상률을 두지 않습니다.

## 4. 실제 결과와 대시보드 읽기

질량·축응력·축변위의 독립적인 이론 확인식은 두께 t(mm)에 대해 다음과 같습니다.

- 질량 = `1.57e-5 * t` tonne
- 축응력 = `50 / t` N/mm²
- 끝단 축변위 ux = `0.0238095238 / t` mm
- FIX 집합 x방향 합력 = −1000 N

`disp`는 ux만이 아닌 변위 벡터 크기입니다. 포아송 수축과 셸 확장 절점 때문에 위 ux보다 조금 큽니다. 임의 허용오차를 늘려 일치시키지 말고 원 DAT/FRD와 단위·집합·프레임을 확인합니다.

아래 값은 이 입력을 **실제 CalculiX 2.22**로 두께 1/2/3 mm에서 실행해 얻은 소규모 입력 검증값입니다(2026-10-27). LHS가 반드시 이 세 두께를 포함하는 것은 아니며, 이 값으로 GUI 결과를 채우지 않습니다.

| 두께 mm | DAT 질량 tonne | 최대 변위 mm | 절점 von Mises N/mm² | FIX Fx N |
|---:|---:|---:|---:|---:|
| 1 | 0.0000157 | 0.02385235 | 49.998 | −1000 |
| 2 | 0.0000314 | 0.01192626 | 24.999 | −1000 |
| 3 | 0.0000471 | 0.00795086 | 16.666 | −1000 |

질량·반력은 이론값과 표시 정밀도에서 일치하고 응력의 차이는 약 0.004%입니다. 이것은 균일 인장 연결 확인이며 메시 수렴·일반 구조 안전성·대형 MDO 성능의 검증이 아닙니다. 출력에는 해당 솔버 버전과 모든 원파일을 남깁니다.

- **Pareto**: 선언한 제약을 만족하는 계산 표본의 비지배점입니다. 기본 목적 순서에 따라 축 이름을 확인하세요. 가장 가벼운 유효 표본을 고르는 것은 이 9점 중의 선택이며 전역 최적해 보장이 아닙니다.
- **Response Surface**: 실제 표본에 적합한 GP의 1차원 반응 슬라이스입니다. 관측점·예측 평균·불확실성 띠를 구별합니다. 별도 `Fit Surrogate`나 3D 회전 조작은 없습니다. 띠가 좁다고 예측 정확도가 검증됐다는 뜻은 아닙니다.
- **Sensitivity**: Spearman 순위 상관입니다. 이 예제는 변수 1개이므로 순위 비교 자체는 의미가 제한됩니다. Sobol 기여율이 아니며 자료 부족 시 가짜 막대를 만들지 않습니다.

NSGA-II 세대별 탐색과 예측점의 자동 FE 재평가는 이 GUI 절차에 포함되지 않습니다. 현재 계산한 후보를 선택합니다.

## 5. Set as Current로 안전하게 적용

1. 유효한 완료 행을 선택하고 변수값·응답·실행 근거를 확인합니다. 실습에서는 `FEASIBLE` 후보 중 원하는 질량/변위 절충점을 고릅니다.
2. **Set as Current Design Point**를 누릅니다. 원본과 계산 당시 입력의 개정이 맞는지, 선택점의 실행 결과가 유효한지 검사합니다.
3. 성공 안내 후 실습 폴더에서 `.inp.bak` 백업과 치환된 `.inp`를 확인합니다. 기존 백업은 보존됩니다. 쓰기 실패나 외부 파일 변경이 있으면 성공으로 표시하지 않습니다.
4. 텍스트 편집기로 `*SHELL SECTION`의 숫자가 선택한 thickness와 같은지 확인합니다. 백업에는 토큰 템플릿이 남아 있어야 합니다. 이 동작은 INP를 수정하며 원래 FreeCAD 문서는 바꾸지 않습니다.
5. 실제 설계에 채택하기 전에는 적용된 덱을 별도 네이티브 계산으로 다시 확인합니다. 여기서는 이미 계산한 점의 입력을 적용한 것이며 예측만 한 점을 실측으로 승격한 것이 아닙니다.

선택점 적용 후 탐색을 계속하려면 연구에 보존된 템플릿을 사용합니다. 숫자로 치환된 INP를 새 연구로 열면 토큰이 없어 변수 탐색을 구성할 수 없습니다. 템플릿 백업을 별도 이름으로 복원해 새 연구를 시작할 수도 있습니다.

## 6. 저장·재열기와 실패 복구

**File → Save Study…**로 실습 폴더에 `tension-study.json`을 저장합니다. 창을 닫고 다시 실행한 뒤 **File → Open Study…**로 같은 연구를 엽니다. 변수·목적·제약, 설계점, 보존 템플릿과 실행 참조를 확인합니다. 재열기 자체로 솔버를 실행하지 않습니다.

연구 JSON만 옮기면 원본·실행 파일까지 이동하지 않습니다. 실습 폴더와 `.caelab_mdo` 실행 자료를 함께 보존하고 원래 경로에서 다시 여세요. JSON은 결과 검토·재개용 기록이지 서명된 인증서가 아닙니다. 원본·결과·매니페스트를 임의 편집한 연구에 과거 계산의 신뢰를 부여하지 않습니다.

| 증상 | 확인·복구 |
|---|---|
| 솔버 없음 | CAELAB_CCX의 실제 파일 경로 확인 후 창 재실행 |
| 설계점 없음 | Configure Study에서 변수/목적 설정 후 Generate DoE |
| 덱 없음 또는 GE 사양만 열림 | 실제 템플릿 INP 열기. 큐브로 자동 대체하지 않음 |
| 응답 누락 | 해당 실행 job.log, FRD/DAT와 출력 키워드 확인. 실패점은 적용 불가 |
| 원본 변경으로 적용 거부 | 변경 이유를 확인하고 새 입력으로 연구·계산을 다시 구성 |
| 결과/실행 폴더 누락 | 보존한 원본 실행 자료 복원 또는 재계산. JSON 수치를 실측 대용으로 사용하지 않음 |
| 적용 쓰기 실패 | 파일 잠금·권한 확인. 원본/백업을 확인한 뒤 재시도 |

출력 의미의 근거는 [CalculiX 공식 매뉴얼](https://www.dhondt.de/ccx_2.23.pdf)의 단위(§3), 셸(§6.2.12), EL PRINT(§7.53), SHELL SECTION(§7.118)과 [공식 DAT 출력 구현](https://github.com/Dhondtguido/CalculiX/blob/master/src/printout.f)입니다. 이번 실제 입력 검증에 사용한 버전은 2.22이며, 매뉴얼 출처의 버전과 구별합니다. 전체 제품의 검증 상태는 [CURRENT_STATE](../../CURRENT_STATE.md)를 따릅니다.
